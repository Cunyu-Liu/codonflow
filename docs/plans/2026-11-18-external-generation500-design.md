# Protein-only 外部500请求补实验协议（2026-11-18）

## 必要性

独立外部审计SHA256=`b7e3f58964dcefe9b6532f9f2dfb7854bb7e363df8494b5407125e3560c0c1fc`确认：LinearDesign在54个run中无B≥50覆盖，codonGPT覆盖B=100，GEMORNA仅18/54覆盖B=50，均无B=500。现有小样本不能支撑CodonFlow相对外部方法的500预算胜负。

## 冻结规则

- 输入：unique18全部18基因、seeds0/1/2，protein-only语义，不与natural-source混表。
- 方法：官方codonGPT和GEMORNA生成器、既有冻结checkpoint和环境；每个record/seed请求500个候选。不得根据中途质量或唯一解数量追加请求。
- 输出：独立`eval_outputs/a7_external_generation500/`。不得覆盖或拼接A6旧100结果。每文件保留请求数、真实唯一解、重复/非法/排除、代码与模型版本、生成成本。
- 请求500不保证500唯一解；缺失预算如实报告，不能把旧100结果补齐到500，也不能请求到某方法获胜才停止。
- LinearDesign保持实际DP输出，不把扫描变体冒充500样本。其公平比较限实际预算，不伪造B=500。
- 生成完成后按`a7_recompute_external.py`重新计算全部目标，不能把生成器原始评分或旧motif计数直接代入。
- GPU：codonGPT和GEMORNA均必须真实CUDA；若CUDA不可用或静默CPU降级，立即停止并留证。最多4个并行生成任务，避免挤占其他项目。
- 成本：生成时间与后续评分时间分开。旧A6生成时间与A7端到端时间不得直接求比；若做严格时间比较，必须另做统一端到端测量。
- 统计：先完成全部54个生成/排除结果再汇总，不挑选基因。任何B=500比较必须每方法实际达到500唯一解，缺失预算不得当0。

## 验证

先真实500候选工程检查，验证输出schema、真实CUDA、请求数和唯一解统计，再resume完整54任务。完整结果需独立重算目标、AUC/NED、identity、预算覆盖和输入SHA；仍属于开发证据，不直接宣称SOTA或生物学有效性。confirmation24是否使用另行评审。


## 技术修正1：GEMORNA生成模式

首次持久循环500候选仅产生3个唯一解，而旧同基因100个独立官方进程产生85个唯一解。两种模式的输出多样性不可混用。独立官方进程5/5唯一解对照通过，因此全量执行器固定`CODONFLOW_GEMORNA_PERSISTENT=0`。持久循环结果隔离保留，不进入比较；恢复时codonGPT有效500解跳过，GEMORNA仅重跑缺失的独立进程结果。生成成本按实际独立进程记录，不能用持久模式时间替代。
