## 6. 联合 HV 口径统一 + 新聚合器（本轮第二个实质产出）

发现两条 A6 代码路径的归一化口径不一致：

- `scripts/run_a6_rollout_pilot.py::summarize_arms`（protocol v2）：参考点与 scale **都用 ptp**（max−min）；
- `scripts/recompute_s3_full_adaptive.py::pooled_reference`（主表口径）：参考点用 ptp，**scale 用 `q95 − min`**。

两者算出的 HV 不可直接比较。若 G2 的 pilot HV 与 G3 的主表 HV 混用，就是口径混算。

处置：
1. pilot 的 scale 统一为 `q95 − min`（退化轴用 1），protocol 名升级为
   `joint_all_arms_min_minus_5pct_ptp_q95_scale_v3`；参考点仍是 `min − 5%×ptp`（与 pooled_reference 一致）。
2. 新增 `scripts/a6_joint_hv.py`：把 CodonFlow 三臂与五基线放进**同一唯一并集参考域**重算 HV，
   缺失方法写入 `missing_methods`（不记零分），退化轴拒绝并报轴号，重复向量只计一次。
3. 验证三遍：
   - `--self-test` 5 条不变量（参考点处 HV≈0、加入支配点 HV 不降、重复向量不膨胀、退化轴拒绝、scale 由 q95 而非 max 决定）；
   - 真实 artifact 干跑（smoke pilot + `core_s0/egfp`）：8 个方法全部入表、`missing=[]`、286 个并集点；
   - 全量回归：`103 passed, 1 skipped`（新增 5 项契约测试；旧 protocol 断言按新口径更新）。
4. 干跑数值（cf_base 0.083 / immediate 0.091 / short_rollout 0.091 vs LD 2.271、GEMORNA 1.711、
   GPT 1.369、greedy 1.383、uniform 0.274）来自 4 解、T=2、未收敛 checkpoint，**不是科学结论**，
   只是“代码能跑通、口径一致”的证据。

同轮还确认：直线基线里的 GC 目标硬编码 0.55，与 `configs/atc_norm.yaml` 的 `gc_target: 0.55` 目前一致，

## 8. 02:58 事故：edited-token 第 7 轮末尾 OOM（撞硬上限）

- 位置：`e7 b35400/35442`（99.9%），`Tried to allocate 1.74 GiB`，`7.05 GiB allowed`、`6.23 GiB allocated`。
- 根因：长度分桶里存在超长序列批（单条可达 ~6 kb），注意力激活出现尖峰，超过 0.30 的硬上限。
  **不是显存被别的进程挤占**：当时 full-token 11.07 GB、unique18 0.5 GB，卡上仍有 5.42 GB 物理空闲。
- 代价：epoch 7 没有落盘，整轮丢失（约 3.3 小时）。
- 处置：11:50 用 `--gpu-mem-fraction 0.42`（≈9.88 GiB）从 epoch-6 `training_state.pt` 重启；
  micro-batch 10000 / accum 6 与有效 batch 60,000 保持不变，可比性披露不变。
- 教训：**cap 要按"最坏批次"设，不能按稳态设**。下次启动前应先估算最长序列批的激活峰值。

## 11. GitHub 凭证（2026-10-31 解决，所有集群通用）

- **根因**：px2-jcy 新实例的 `~/.ssh` 只有 `known_hosts`，没有任何私钥；仓库 remote 是
  `git@github.com:...`（SSH 协议）→ `Permission denied (publickey)`。不是网络问题：
  22/443 端口通、`api.github.com` 返回 200。
- **方案**：一把 repo 级 deploy key（read-write），私钥 `~/.ssh/codonflow_clusters_ed25519`，
  已装到 px2-jcy，并在 `~/.ssh/config` 里把 `github.com` 固定到该身份（`IdentitiesOnly yes`）；
  此前那次性生成的 `id_ed25519` 已删除，避免多身份混淆。
- **注册**：GitHub deploy key `clusters-shared (2026-10-31)`，`read-write`，仅限本仓库
  （比账号级 key 的爆炸半径小；一旦实例回收或泄漏，删这一条即可）。
- **新集群接入**（用户机器上的脚本，非本仓库内容）：
  `CLUSTER_PASSWORD=... ./install_cluster_github_key.sh root@<host> <port>`
  注意：该网关**拒绝 scp/sftp**，脚本改走 base64-over-ssh 单通道；且主机名默认补 `root@`。
- **验证**：`ssh -T git@github.com` → `Hi Cunyu-Liu/codonflow!`；
  `git push` → `Everything up-to-date`；`origin/main == HEAD == b809f8f0`。
