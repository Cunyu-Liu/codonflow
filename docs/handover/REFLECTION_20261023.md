## 第一部分：项目当前存在的问题（按严重度排序）

### P0-1 绝对多目标覆盖落后 2–4 倍（科学故事的最大威胁）

**现象**：L1 主表 S3 场景，CodonFlow HV 128±17 vs LinearDesign 484±74、codonGPT 249±59（预印本 §5.4）。S2 同样落后（32 vs 109）。

**为什么致命**：审稿人第一眼看到主表就是"你的方法比两个基线差 3 倍"。预注册里我们只承诺"双/四目标 hypervolume 与非支配率领先 ≥10%"（R7/EXP-5），但实际没达到——这是预注册口径内**未兑现的主断言**，目前只能降级为 trade-off 报告。这不是汇报口径问题，是真实的能力差距。

**根因链（三因素诊断，已有证据）**：
1. 协议差异（已修）：10× AR 采样变体已补；
2. 奖励效用退化（已修）：ATC Tchebycheff 零权重轴 bug 修复后 S3 +12.2%/+12.8%；
3. **基座容量不足（当前主要矛盾）**：56M 模型 × 862k 语料的条件分布容量有限。容量曲线显示 862k 语料让 56M 多用 13 个 epoch 才追平 v2-215k 的收敛值（2.8069 vs 2.8141，几乎打平），说明 **56M 已经吃满了 862k 语料的可学信息**——数据再多也挤不出更多，必须扩参数。

**改进方案（本轮核心实验路径）**：
- 355M 续训至真收敛（e13=2.7921 已低于 56M 收敛值，且停时仍在下降）→ 全量评测链 → 若 S3 HV 相对 56M 提升 ≥10%，则容量假说闭环，主表翻身的唯一机会就在这里；
- 同步做「解预算扩展」对照：355M + 300 解/基因（LD 同等预算），验证容量×预算交互；
- 若 355M 仍落后：接受预注册的降级路线（trade-off 报告），但把故事重心完全压到 P0-2/P0-3 的不可替代优势上（见第二部分故事线重构）。

**验收标准**：converged.pt 产出 + 17/17 评测 JSON + 与 56M 同表对比 + fig10 容量曲线第三点落定。

### P0-2 RLOO 增益存疑——方法学第二支柱不稳

**现象**：v3 基座上 RLOO 35 iters 即 plateau（v2 基座要 111 iters）；已出的 6 个对照 arm 混合（egfp_s0：158→136 ↓13.8%；nluc_s1：83→87 ↑4.3%；nluc_s2：92→97 ↑5.4%；zfish_s0：122→112 ↓8.3%；zfish_s1：131→124 ↓5.9%；zfish_s2：121→133 ↑9.8%）——正负各半，噪声级差异。

**为什么致命**：预印本的第二个贡献点是"label-free dual-reward RLOO recipe"。如果 RL 在新基座上增益消失，这个贡献点塌掉一半（v2 基座上 RLOO v4 系列曾有明确正增益：4.43 vs 3.51）。

**根因分析（假说，待 9 arm 裁决）**：
- **假说 H-rl**：「v3 基座预训练已把奖励可提取的信息吃掉大半，RLOO 边际增益自然缩小」——与 P0-1 的容量诊断一致但方向相反：56M 容量小 → 奖励信号学得快也饱和快。
- 备择假说：35 iters 收敛过快本身可疑（学习率/正则配置在新环境复刻时可能有偏差），需检查 RLOO 训练日志的奖励曲线形态。

**改进方案**：
1. 补全 9 arm 评测（egfp_s1/s2、nluc_s0、mouse×3、fly×3）→ 3×5 基因-种子矩阵全量裁决；
2. 若确认无增益：预印本如实改写为「RLOO 增益依赖基座预训练充分度：215k 语料基座 +RL 提升显著，862k 基座 +RL 增益消失」——这本身是有价值的 scaling 洞察（data scaling 与 RL scaling 的替代关系），不是失败，是 trade-off 刻画；
3. 关键加分项（如果时间允许）：在 355M 基座上跑一版短程 RLOO，构成「容量-数据-RL」三角关系图——预印本 §6 的核心科学图。

### P0-3 评测器参考域问题残留（数据质量层）

**现象**：
- Cas9 S3 motif 罚分未做长度归一化（4104nt vs 500nt 的 motif 数量天然差 8 倍，尺度不可比）——**已知 bug 未修**；
- yeast g08 HV 零域（已用 §5.7 adaptive reference 口径剔除，但那是补丁不是修复）；
- g02 mouse −47% 大退化（S2 反升 +35%，疑与 mouse 2.2kb 长基因 + GC 目标 0.55 不适配 mouse 家族有关——§5.7 已指出 GC 目标是家族相对的）。

**改进方案**：
1. 修 Cas9 motif 长度归一化（motif_penalty / n_codons），重跑 Cas9 S3 臂（~1h GPU）——列入本轮必做；
2. 把「per-gene adaptive reference」从补丁升级为正式口径（amendment 记录），所有 S3 HV 全部按 adaptive 口径重算一遍（只需重算，不需重新生成——obj_vectors 都在 JSON 里）；
3. g02 现象写进论文作为「fixed GC target 的家族相对性」证据，与 GEMORNA 的 GC 偏差互相印证（已有素材）。

### P1-4 数据集规模与 spec 承诺的偏差

- spec R2 写「≥1M CDS（300 万为目标）」，实际 v3=862k（25 物种）。**偏差已如实记录**，且容量研究证明 862k 已让 56M 饱和——继续堆数据对 56M 无意义，对 355M 边际收益存疑。
- 决策：不再扩语料（一个月 deadline 内性价比为负），预印本如实报告 862k + 容量饱和证据。**不做无意义的返工。**

## 第二部分：科学故事主线重构（从课题到论文的逻辑链）

**当前问题**：叙事散点化——六个 EXP 各自有现象，但「问题→方法→证据→结论」的推理链没有形成闭环递进；摘要里正负结果并列，读者抓不住主线。

**重构后的主线（一句话）**：

> 把约束写进分布、把偏好写进过程、把标注从奖励里拿掉——这三件事在 mRNA 密码子设计上分别兑现了多少，剩下的差距被容量研究定量解释。

**三幕结构（每幕一问一答一证据链）**：

**第一幕（问题真实存在）**：synonymous 设计的硬约束怎么被现有方法处理？→ 三条路线各有代价（masking 塌多样性、搜索烧预算、过滤浪费）→ 证据：EXP-1 KS p<0.05 + EXP-2 Wilcoxon 6.1e-5 + Cas9 AR 1024 墙。
**第二幕（by-construction 兑现了什么）**：门控终端分布把合法性变成分布性质 → 100% identity/legal × 4500 解 × OOD 零衰减 × 4.1kb 长序列 + 门控/偏好双通道独立可控（ATC 修复前后对照 +12%）+ 同预算下 time-to-first-usable 优势。
**第三幕（没兑现的部分去哪了）**：绝对 HV 落后 2-4× → 三因素归因（协议已修/效用已修/容量未决）→ 容量曲线三点（215k-56M / 862k-56M / 862k-355M）+ 数据饱和证据 + RL 增益随预训练充分度衰减 → 「下一步是容量与预算，不是方法论」的定量 frontier。

**承上启下检查（每环必须被上一环的结论逼出来）**：
1. 第一幕结论「约束外置有代价」→ 逼出问题「约束能内置吗」→ 第二幕开头；
2. 第二幕结论「合法性与偏好通道独立可控，但绝对覆盖落后」→ 逼出问题「差距归因」→ 第三幕开头；
3. 第三幕结论「容量是 frontier」→ 直接给出 roadmap（355M→1B、预算扩展、家族自适应参考）。

**摘要重写原则**：正向断言放前（100% 保证 + 机制可控 + 效率），gap 放后且带归因（不是「我们输了」而是「差距被三因素解释且两条已修复」）。

## 增补：2026-10-25 交接会话反思（355M 收敛后）

### 状态跃迁：P0-1 的裁决已过半

A4 时「355M 容量档是主表翻身唯一机会」——现在预训练侧已兑现（2.7875 vs 2.8069，-0.70%，且 56M 时代的数据饱和被打开）。**但预训练损失下降 ≠ 下游 HV 提升**（P0-1 的真正裁决在 35 JSON 评测，预计 10-26 齐）。纪律：在 JSON 齐前不写任何「容量已解决」的结论性文字——v3-56M 的教训（862k 语料只带来 -0.25% 损失但 HELD18 S3 +10.8%）说明两侧可以脱钩，方向不确定。

### 本次自查发现的工程问题（已修）

1. **评测脚本 56M 硬编码**：355M 权重一加载就 size mismatch——上一会话在 /home 副本打了 arch 自动检测补丁但未同步 code_repo 快照、未推 GitHub。教训：**补丁必须当会话推送**，跨会话遗忘风险高（本次靠 3 遍 diff 检查才发现两副本不一致）。
2. **集群 SSH key 失效**：GitHub push 权限断（publickey denied）。已建立 bundle 中继通道（集群→本地 scp→本地 push）。待办：恢复集群侧 deploy key 或 token。
3. **rloo_backfill c0/c1 闪退误判**：脚本幂等跳过即退出是正常行为，不是故障——排查时差点误杀。教训：幂等脚本的「秒退」要先查目标 JSON 是否已存在再判死活。
4. **fly_s2 手动臂的 $OUT 转义事故**：tmux 命令里 \$OUT 未展开写到根目录 /E5_...json——发现后已清理重跑。教训：**tmux new-session 里的 shell 变量必须写绝对路径**，不吃外层变量。

### 科学故事线：当前卡点与解法

主线三幕已立（REFLECTION 第一部分），当前处于第三幕数据补全期。新增一个叙事资产：**容量三点曲线本身成为 fig10 的主叙事**（215k/56M→862k/56M→862k/355M 的两级台阶：数据台阶 -0.25%、容量台阶 -0.70%——容量效应是数据效应的 2.8 倍）。这把「绝对 HV 落后」的第三幕从「差距归因」升级为「正面的 scaling 定律刻画」——不管 355M 下游裁决如何，这条曲线都成立且是论文的独立贡献。
