# RK-06a dense-v2 / actual-set evaluator audit

## Bounded scope

This audit closes only the dense anytime formula and actual-output-set schema/evaluator. It does **not** claim that a real B=500 trajectory, strong-baseline run, independent raw-sequence scorer, model improvement, or untouched functional evaluation has completed.

- Legacy `anytime_curve` remains unchanged for backward compatibility; it is sparse trapezoid AUC with a synthetic origin and is not renamed as dense-v2.
- New `dense_budget_step_auc_v2` requires exactly one real finite objective vector at every integer budget `B=1…Bmax`. Missing, duplicate, zero, non-integer, out-of-range, NaN, and wrong-dimension inputs are rejected.
- Formula: `sum(HV_b for b=1…Bmax-1)/(Bmax-1)`. No synthetic `(0,0)`, no trapezoids, no zero filling. Bmax is returned as an endpoint but excluded from AUC.
- `summarize_actual_set` reports actual Pareto points and hypervolume. `curve`, `area`, and `dense_budget_step_auc_v2` are null for an actual set; duplicate objective vectors do not become extra Pareto points.
- `configs/a8/actual_set_schema.json` requires actual output CDS/hash/objectives and explicit cache-before-requests, unique scorer, forward, generation/scoring/wall-clock time, hardware and parallelism fields. Unknown costs are null with reasons, never fabricated zeros.

## Synthetic hand-value verification

Three one-dimensional points at budgets 1/2/3 have cumulative HV 1/3/3. Dense area is `1+3=4`, denominator is `2`, AUC is `2`; B=3 remains an endpoint. A separate constant-HV B=500 case checks area `998`, denominator `499`, AUC `2`.

The actual-set case contains `[1,0]`, `[0,1]`, `[2,2]`; only `[2,2]` is Pareto-optimal and normalized HV is `4`. Actual-set dense metrics remain null.

`evaluator_synthetic_verification.json` contains 10/10 PASS checks generated by `scripts/a8_rk06_verify_eval.py`. This is synthetic protocol verification, not model performance.
